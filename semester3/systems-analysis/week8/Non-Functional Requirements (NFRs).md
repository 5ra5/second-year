Questions related to NFRs:
- How should the system do what it does?
- How must the system be built?
- How should the system be built in terms of engineering process?

Three categories of non-functional requirements:
- Quality requirements
- Process requirements
- Constraints

example: The web inventory system shall by delivered by 3rd quarter? - process requirement
example: The web inventory system shall complete every business process within 7 mouse clicks - quality
example: When a stock empty notification arrives, the web inventory system shall display a warning to the user - functional requirement


- Qualitative properties of the system can only be measured by talking to the users
-  They are hard to pin down - we usually don't  know about them unless we talk to the right stakeholders

Quality Requirements
- Quantitative characteristic ("Quality in use")
- Characteristics

1. Choose a foundational quality model
2. Describe the characteristic
3. Define a metric and threshold
4. Define how the metric will be measured
5. Provide a rationale for the characteristic e.g.

- Saying that the system is intuitive or user friendly is too broad when dealing with identifying quality requirements
- We need to break it down into something that can be measured (number of mouse clicks - click distance to complete a task, simple Usability Scale score, minimum contrast between colours, font size > 10...)
- These things give us an actual value of the quality of the system
- Test the system with a sample size of users to approximate the quality of the system

Process requirements
- project specific

Constraints
- implementation constraints and limitations
- operational environment

Quality Model ISO 25010
- Reliability
- Efficiency
- Maintainability
- Usability - goes up and down based on how we design the system, "how easy is it to use"
- Portability - the ease with which software can be installed
- Scalability - ability to handle a wide variety of configuration sizes
- Flexibility
- Performance - common quality dimensions
