# Test organisation

- user acceptance testing is testing done against user requirements
-  **who does testing**: programmers (ad hoc, sub-system), other team members (sub-system), users with support (user acceptance testing), independent organisations

## Test team roles

-  test manager (test lead) - project manager for the project testing, they plan, organise, manage and control the testing. 
- tester - they write test cases, define the expected results from the requirements and specification documents, prepare test procedures and environments as well. they also re-test after a change in the code and regression tests (re-testing to make sure that fixing one aspect of the code didn't break another)
-  test analyst - scope the testing, conduct expert interviews, document test specifications, liaison with test environment manager, technicians, user, testers, prepare test reports
-  **important to know the difference between test manager and test analyst**
-  test automation technician - similar to a tester - they record, code and test automated scripts

## Support staff

- DBA
-  system network administrators
-  toolsmiths
-  experts to provide direction

# Test Planning and estimation

-  first we need to start with high level test planning
-  we have a more and more detailed plan as we go along
-  before we start execution we have a maximally detailed plan (eg. test this function, press this button etc.)
-  tests are usually run 3 times if they are complex, 2 times if they are simpler, and only once if they are even simpler
-  you need to think about your resources, people suitable for specific tests, test policy of the organisation
-  you need to plan and re-plan during the testing project
-  you can't predict how many defects you're going to find and how many re-tests you will need to take, so it's hard to plan ahead


## Exit criteria

**candidate question for the CA exam**
  - exit criteria when to stop texting in the context of the testing stage, it doesn't apply to a single test
  -  they consist of thoroughness measures (if you are covering enough of the functionality), cost, estimates of defect density or reliability measures
  -  residual risks such as defects not fixed or lack of test coverage in certain areas
-  they should be objective and measurable
