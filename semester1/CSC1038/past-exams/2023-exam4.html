Introduction

This is your first assessment for the CA284 Systems Programming module. Take note of the following:

  1. This is worth 40% of your overall grade.

  2. This assessment is due at 17:00 on Thursday 14th December 2023. NO code received after this deadline will be graded.

  3. This assessment is an *Individual Assignment*. You should familiarise yourself with the DCU plagiarism policies, and other documents which describe academic integrity. PLAGIARISM IS NOT TOLERATED AT ANY LEVEL!

You will be uploading your solutions to Einstein (https://ca284.computing.dcu.ie/einstein).

Marking

The submission solutions for each task will be assessed in terms of the correctness, solution approach, coding style and the ability to use encouraged concepts.

Correctness (40%)

The correctness of the submission will be checked automatically with Einstein. You will upload your work in the usual way. Please note that the correctness of the solution only has 40% overall weight.

Solution approach and Coding style (55%)

In addition to the correctness, all submissions will also be reviewed for solution approach and coding style. For example, marks will be deducted for

  • poor solutions (e.g. hard code to print the testing results instead of implementing a suitable algorithm);

  • very poor algorithms;

  • inadequate use of functions to design the solutions;

  • failure to use the C techniques where required or encouraged;

  • failure to include adequate introduction and necessary comments;

  • not using function prototypes;

  • poor code representation;

  • etc.

However, it also means that the incorrect solutions still earn some marks for style and approach.

Please try to use functions to design your solution. A correct submission including everything inside the main function or write a function that does many things will lose points.

Even if you cannot produce a complete solution for some tasks during the exam period, just try to present the code as best as you can and upload to Einstein. You can still earn some points if the submissions demonstrate a suitable approach for solving the task and the code is well presented even though it cannot pass all the tests. So presentation is important here.

Wow factor (5%):

  • A 5% of the mark will be given for a "wow"/creative algorithm/solution design OR for the use of some advanced concepts (e.g., function pointers, pointers, dynamic memory allocations) where possible.

Note
 It will not be possible to provide detailed feedback to all students. Therefore, if you can complete all given tasks early, you may want to spend the remaining time to review the code, ensure the code convention and that your solutions are best presented as well as improving the algorithms and implementations.

Expected coding template for each task

Generally, each submitted solution is expected to contain the following sections:

  • Heading:

    1. A brief introduction about the program (author, description, date);

    2. A brief description about the approach you are going to follow to solve the corresponding task (a few short sentences or bullet points should be sufficient);

    3. Include necessary libraries;

  • Body:

    1. Function prototypes;

    2. The main function;

    3. The implementation of each function (already declared in function prototypes);

    4. Clear comments at where you think it is necessary to help the readers to understand your code more easily. For example, a short description can be added at the beginning of each function to describe the target of the function, the meaning and accepted values of each parameter and the return value of the function.

Note
 At this stage, you can use any concepts in C as long as it meets the tasks' requirements.

Task

1. Student Attendance Record (35%)

Write a program ex4-attendance.c which accepts n number of attendance records for n students. Each record contains a sequence of characters, where each character refers to the attendance status of the student as follows:

  • 'P' = Present

  • 'A' = Absent

  • 'L' = Late

A student will have attendance status = 1 if their record contains greater than or equal to three absent-equivalent checks. In particular, each 'A' refer to an absent check. Three consecutive 'L' are also equivalent to an absent check._ Otherwise the attendance status will be 0.

You can assume that the maximum number of entered records is 50.

The program display the attendance status of all students line by line.

Input

./ex2-attendance PAPPLPLA PPLLLPPPAPPPA APPPAPPA AAPPPPPP PAPAPAPA AAAALLLLLL PPPAPAPLLPLLLP APLPPLAPLPP

Output

0
1
1
0
1
1
1
0

2. Find a longest or shortest sentence in a paragraph (30%)

Write a program ex4-longest-line.c which accepts two arguments from the command line. The first argument is a paragraph and the second argument is a selection of shortest or longest. Based on the value of the 2nd argument (i.e., 'shortest' or 'longest'), the program then finds the shortest or longest sentence (i.e., the sentence with the smallest or largest number of characters) in the paragraph.

The program displays the length of the sentence in the first line and the found sentence in the second line. If the 2nd argument is neither longest nor shortest, the program shows the message Not valid!. Please note the following points when identifying a sentence:

  • A sentence starts with any character except for a space, and ends with a dot . or question ? character;

  • However, there is an exception that the content within a single quote are considered a part of the sentence where the quote locates, even if the content contains a dot .. For example, the whole content My friend said to me: 'It is true. You are very strong.'. is considered as a sentence. Although It is true. and You are very strong. end with a dot ., they are within a single quote so they are a only part of the outer sentence.

  • The length of a sentence refers to the number of characters in it, including the ending dot . or question ? character.

You can assume that the maximum length of a sentence is 200. Remember to print \n at the end of the program.

Example:

Input

./ex4-longest-line "Well if more women do cry in our workplace, why is that the case? Because men are not, they are more denied permission to cry, from a very young age. And even if you think – I mean, I have got my own kids at home and I see all the time. I have got three girls and a boy and people meet my girls and they comment on their appearance and they meet my boy and they talk about how brave he is and how strong he is. So, from the very, very get-go we are conditioning people, based on their gender, to determine what type of response they should have in certain situations." shortest

Output

65
Well if more women do cry in our workplace, why is that the case?

Input

./ex4-longest-line "Haha. Heheh hehe he. 'Heheh hehe. hoho kaka kaka'." longest

Output

29
'Heheh hehe. hoho kaka kaka'.

Input

./ex4-longest-line "Haha. Heheh hehe he. 'Heheh hehe. hoho kaka kaka'." longestest

Output

29
Not valid!
Note
 Please note that in the examples above, the double quotes are only used to cover the string arguments in the command lines and not a part of the arguments.

3. No more duplication (35%)

Write a program ex4-duplicate-remover.c which accepts n arguments of integers. The program needs to store all the input integers in an array or a linked list. Then the program has a function to remove all duplicated numbers and print all non-duplicated elements. Note that the duplicated values are removed completely, including the value itself.

Please note that the removing process is required to be done in place in the array or linked list where the list of numbers are stored. In other words, there is only a single storage (array or linked list) allowed in this task. The use of a second storage may cause a significant mark deduction for solution design.

Input

./ex4-duplicate-remover 1 2 2 3 4 5 5 5

Output

1
3
4

Explain: 2 and 5 are eliminated from the list because these values are duplicated.
